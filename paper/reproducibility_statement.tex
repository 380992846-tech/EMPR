\section{Reproducibility}
\label{sec:reproducibility}

\paragraph{Code and version.}
All code, evaluation scripts, and analysis utilities are released in the
accompanying repository (\url{https://github.com/380992846-tech/EMPR}) at the
exact commit used for this paper
(\texttt{ec5d0c02c35660a3ac83fc27a1b67de9f0b9df6d}). Defaults live in a single
configuration file (\texttt{config.yaml}); each analysis stage has a single
entry point. Every result file records its own provenance in a
\texttt{meta} block (\texttt{git\_commit}, execution environment,
\texttt{prompt\_fingerprint}, \texttt{max\_new\_tokens},
\texttt{chat\_template}, \texttt{wall\_time\_s}), so any number in the paper can
be traced to the run that produced it.

\paragraph{Datasets.}
\textbf{SciBench} physics (\url{https://github.com/mandyyyyii/scibench};
subjects matter, class, fund, diff, quan, thermo) yields $N_{sci}=323$
problems, of which mechanics 56, thermodynamics 66, optics 47, math 50,
quantum 33, general 71. All 323 reference answers are numerically gradable, so
no sample is excluded from the denominator of the main table.
\textbf{OlympiadBench} physics
(\url{https://huggingface.co/datasets/Hothan/OlympiadBench}; configs
\texttt{OE\_TO\_physics\_en\_COMP} and \texttt{OE\_TO\_physics\_zh\_CEE}) yields
351 problems, of which only 152 (43.3\%) have a numerically gradable reference
answer; the remaining 199 are symbolic or multivariate solutions and are
excluded from the denominator (reported as \texttt{n\_unscored}).
\textbf{MMLU} physics (\texttt{cais/mmlu}; high-school, college and conceptual
physics) yields 488 multiple-choice problems. All datasets are public and are
fetched by \texttt{scripts/download\_data.py}; SciBench is loaded from the local
\texttt{data/} copy when present so that the exact same 323 problems are used on
every machine (\texttt{EMPR\_PREFER\_HF=1} overrides this).

\paragraph{Models.}
All models are open-weight and were run from public checkpoints:
Qwen2.5-3B-Instruct, Qwen2.5-7B-Instruct, Qwen2.5-14B-Instruct,
Meta-Llama-3.1-8B-Instruct, and DeepSeek-R1-Distill-Qwen-7B. No closed-weight or
API-only model contributes to any reported number. Causal tracing is performed
exclusively on an open-weight model whose residual stream is accessible
(Qwen2.5-7B-Instruct). Models listed in \texttt{config.yaml} but not reported
here were not run and no claim is made about them.

\paragraph{Inference settings.}
Decoding is \textbf{greedy} (temperature $=0$) with a fixed seed (42), so all
outputs are deterministic. Maximum new tokens were 1024 for chain-of-thought
prompts (1536 for the reasoning-distilled model, whose chains are longer) and
96 for answer-only prompts (64 for multiple-choice and for the sensitivity
probes). Inference used the \texttt{transformers} backend on a single GPU in
bfloat16 with batches of 16--48; vLLM was not available in the execution
environment, so the transformers path was used throughout and no result mixes
backends. The tokenizer's chat template is applied to every instruct model
(recorded as \texttt{meta.chat\_template}) and batch generation uses left
padding.

\paragraph{Answer extraction and grading.}
Correctness is judged by symbolic/numeric comparison. The final answer is
extracted by a precedence-ordered procedure (\texttt{ANSWER:} line, taking the
\emph{last} occurrence; then \texttt{\textbackslash boxed\{\}}; then
``answer is X''; then the last number on the last line), normalised for Unicode
minus signs, superscripts, \texttt{\textbackslash times} and thousands
separators, and compared to the reference under a relative tolerance of 5\%
(absolute tolerance 0.01 for near-zero targets) via the Python/SymPy evaluator.
Reference answers are parsed with a \emph{stricter} parser than model outputs:
a reference that is not a single number (up to units) is marked
\texttt{unscorable\_ref} and removed from the denominator rather than counted
as a model error, because a permissive parser would read
\texttt{x\^{}2+2x} as \texttt{2} and silently corrupt the denominator.
Grading is covered by 23 self-test cases (\texttt{python -m src.grading},
23/23 pass) and by the unit-test suite (83 tests). As an end-to-end check, using
the reference answers as model outputs yields 323/323 self-consistent
judgements. No LLM judge is used for the primary results.

\paragraph{Statistical protocol.}
All reported accuracies carry bootstrap 95\% confidence intervals from
10{,}000 resamples with seed $=$\,42. The bootstrap is implemented in pure
Python using \texttt{random.Random} and order statistics, so the intervals are
reproduced \emph{identically} across machines, independent of the NumPy
version. Pairwise comparisons use McNemar's test (on paired per-problem
outcomes); error-distribution comparisons use an uncorrected Pearson
chi-square; agreement between the two error annotators is quantified with
Cohen's $\kappa$.

\paragraph{Sensitivity probes.}
Three deterministic perturbations are applied to the same 323 SciBench
problems: \emph{numeric} (scale physical values; physics intact; 305/323
problems affected), \emph{wording} (surface paraphrase only, physics and data
bit-identical; 240/323), and \emph{swap} (exchange two distinct physical
quantities, creating a physically inconsistent problem; 36/323). Because the
correct answer to a \emph{numeric} or \emph{swap} variant is not directly
computable, only the distribution of output change is reported for those
variants; \emph{wording} keeps the reference answer valid, so it additionally
supports a paired accuracy comparison. Median and p90 sensitivity are reported
instead of the mean, since the score $|\Delta|/(|base|+\epsilon)$ is dominated
by outliers when $|base|\approx 0$.

\paragraph{Causal tracing.}
We follow the corrupt-and-restore protocol: the numeric quantities of a question
are replaced by a semantically empty placeholder (C2 corruption), the corrupted
prompt is run, and the clean residual stream is restored at exactly one layer
at a time; all other layers remain corrupted, isolating each layer's
contribution. Restoration is applied only during prefill (never to single-token
decode steps), and the clean and corrupted sequences are aligned from the right
because they tokenise to different lengths. Only problems whose clean run was
\emph{correct} and whose corrupted run \emph{lost score} enter the recovery
rate; of 150 attempted problems, 14 qualify (134 skipped as clean-wrong,
2 as corruption-flat), which is the sample size behind the reported curve.

\paragraph{Hardware and compute.}
All runs were executed on a single NVIDIA A800-80G PCIe GPU (112 vCPU,
991\,GB RAM, 50\,GB scratch disk) with bf16 weights. Checkpoints were downloaded
one at a time and deleted after use, so peak scratch usage stayed below 30\,GB;
a single 14B checkpoint needs $\approx$30\,GB free. Total compute for all
reported runs is \textbf{$\approx$2.0 GPU-hours}, of which $\approx$1.65\,h is
the twelve evaluation runs (summed from the \texttt{wall\_time\_s} recorded in
each result file) and the remainder is sensitivity probes, causal tracing and
error annotation. Table~\ref{tab:compute} gives the breakdown.

\paragraph{Reproducibility checklist.}
\begin{itemize}
  \item Deterministic decoding (temperature 0, seed 42): \checkmark
  \item Public datasets + scripted download, pinned local copy: \checkmark
  \item Open-weight models, public checkpoints: \checkmark
  \item Symbolic/numeric grading with 23-case self-test and 83 unit tests: \checkmark
  \item Reference-answer strictness separated from output-extraction leniency: \checkmark
  \item Bootstrap 95\% CI, machine-independent (pure Python): \checkmark
  \item Causal tracing on an open-weight model only: \checkmark
  \item Code, config and per-run metadata at a pinned commit: \checkmark
  \item Error-type annotation cross-checked with a second, cross-family judge: \checkmark
\end{itemize}

\paragraph{Limitations affecting reproducibility and interpretation.}
(i) The \texttt{swap} perturbation covers only 36/323 problems (11.1\%) because
many problems contain quantities of a single type or carry no unit; this is
reported rather than artificially inflated, and the swap results are treated as
supporting evidence only.
(ii) OlympiadBench is evaluated only on the 43.3\% of problems whose reference
answer is numerically gradable; that subset is biased towards easier items, so
OlympiadBench accuracies must not be compared numerically with SciBench
accuracies.
(iii) Error-type shares are annotator-dependent: a same-family judge
(Qwen2.5-14B) and a cross-family judge (Llama-3.1-8B) agree on only
$\kappa=0.133$ (60.2\% raw agreement) on the same 495 samples. Both judges
identify E2 (algebraic/computational error) as the dominant category and E3 as
rare, which is what we claim; the precise E1/E2 split is not claimed, because the
E1/E2 boundary is intrinsically fuzzy (applying the wrong law usually also
shows up as an arithmetic error).
(iv) Unparsed model outputs are counted and reported
(\texttt{n\_unparsed\_pred}), never imputed; on SciBench this count is zero for
all reported runs. A related and more consequential limitation is \emph{format
compliance}: between 71\% and 90\% of chain-of-thought outputs ignore the
explicitly requested \texttt{ANSWER:} line and are graded through the fallback
extractor (``last number on the last line''). Output lengths stay well below the
token budget (mean $\approx$2{,}400 characters, max $\approx$4{,}600 against a
2048-token cap), so this is not truncation, and accuracy does not differ
systematically between compliant and non-compliant outputs (0.21 vs.\ 0.25 in the
matched subset), i.e.\ the fallback does not obviously bias the headline numbers.
It nevertheless means that any evaluation relying on strict output formatting
would measure a lower ceiling than ours.
(v) Throughput figures refer to the transformers backend; vLLM would be
5--10$\times$ faster but is not used here, so wall-clock times are not
comparable across backends.
(vi) Prompt-level scaffolding does not substitute for capability: adding an
explicit ``write down the knowns and unknowns'' instruction changes matched-budget
accuracy by $+2.0$ percentage points (McNemar $p=0.70$, same 150 problems,
2048-token budget), so we do not claim that prompt engineering repairs the
instability documented by the paraphrase probes.
